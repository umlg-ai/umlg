# Видео-демо — Hello Triangle

> Статус: production plan. Вьюер ещё не реализован, поэтому запись начинается после M1.
> Это не замена usability-тесту. Это тест объяснимости и инструмент привлечения.

## 1. Зачем видео

1. **Показать, а не рассказать.** 3D-язык невозможно оценить по скриншоту.
2. **Проверить объяснимость.** Если сцену нельзя связно проговорить за 90 секунд — модель или грамматика слишком сложны.
3. **Привлечь первых пользователей и контрибьюторов.**
4. **Создать артефакт для GitHub:** GIF в README + ссылка на полное видео.

Видео **не** отвечает на вопросы:

- понял ли пользователь, где он находится;
- отличил ли класс от объекта;
- смог ли найти метод;
- сколько времени заняла задача.

Для этого нужен тест с участниками (см. [`../ai-handbook.md`](../ai-handbook.md), раздел 9).

## 4. Текст голоса (RU)

> Это UMLG. Язык архитектуры, в котором нет плоских диаграмм.
>
> Мы находимся в мире замысла. Вот приложение, окно, контекст. А вот `Shader` — призрак. Его нельзя создать напрямую: он существует только как контракт. Чтобы получить шейдер, нужно выбрать, во что он воплотится.
>
> Рядом — граф ресурсов. VAO знает, как читать VBO. Это не картинка: это модель.
>
> Теперь переход. Удерживаю Tab. Мир кристаллизуется: замысел становится воплощением.
>
> Мы всё там же, но теперь это работающий цех. Вот реальный буфер, реальная программа, реальные стадии конвейера. Один draw call — и три вершины становятся треугольником.
>
> Обратный переход — сублимация. Материя становится чертежом. Тот же мир, другая онтология.
>
> UMLG. Архитектура, в которую можно войти.

Реплики должны укладываться в тайминг. Если не укладываются — режется текст, а не кадр.

## 6. Съёмка

### 6.1 Подготовка

- Вьюер M1 работает, `reduced motion` выключен для основного дубля.
- Отдельный дубль с `reduced motion` — для проверки доступности.
- Разрешение: 2560×1440 или 1920×1080, 60 fps.
- Браузер: чистый профиль, без закладок и уведомлений.
- OBS: запись экрана + отдельная дорожка микрофона.
- Сцена: `examples/hello-triangle/`, камера из `layout.json`.
- Отключить курсор, кроме моментов выбора.
- Тёмная тема HUD, контраст ≥ 4.5:1.

### 6.2 Дубли

| Дубль | Что | Зачем |
|---|---|---|
| A | полный проход без остановок | монтаж |
| B | крупные планы элементов | вставки |
| C | переход в замедлении 0.25× | разбор эффекта |
| D | `reduced motion` | доступность |
| E | экран с self-check | конец видео/закреплённый комментарий |

### 6.3 Правила

- Не показывать второй мир сквозь прозрачность — это нарушение языка.
- Не ускорять переход: 1 секунда — часть смысла.
- Не добавлять вспышки > 3 Гц.
- Не использовать чужую музыку без лицензии.
- Не показывать реальные токены/пути/почту.

## 7. Монтаж

- 16:9, 60 fps, H.264/HEVC, аудио −16 LUFS.
- Титры: крупно, sans-serif, контраст.
- Субтитры: RU + EN (файлы `.srt` в `docs/video/subtitles/`).
- Никаких переходов между кадрами, кроме фазового перехода внутри сцены.
- GIF для README: 8–10 с, ≤ 10 МБ, 960×540, 24 fps, только переход M → R.

## 9. Метрики

| Метрика | Цель v0.1 |
|---|---|
| Досмотр Demo | ≥ 50% |
| Переходы на GitHub | ≥ 100 за первый месяц |
| Issues/Discussions | ≥ 5 содержательных |
| «Где я?» в комментариях | ≤ 10% (иначе HUD слабый) |
| «Это же просто 3D-игра» | ≤ 10% (иначе онтология не читается) |

Метрики — не самоцель. Главный сигнал: люди задают вопросы по существу, а не «что это вообще».

## 10. Что делать после видео

1. Собрать комментарии в `docs/feedback/YYYY-MM.md`.
2. Классифицировать: онтология / визуал / переход / курс / техническое.
3. Правки — через issue/RFC, не «на глаз».
4. Повторить видео через 4–6 недель после правок.
5. Сравнить метрики и формулировки.
