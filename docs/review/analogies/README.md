# Analogies as Mods

Метафора — не декоративное решение, а часть языка. Поэтому её замена — это **мод**, который проходит review, scorecard и миграцию.

## Текущий incumbent

**Голографический чертёж ↔ материализованный модуль** (`blueprint`):

- класс — стеклянная витрина с миниатюрой будущего R-модуля;
- объект — монолит-модуль;
- ресурс — стойка памяти;
- процесс — кольцо вокруг ядра;
- стадия — направляющий канал;
- команда — гранёный сигнал;
- актор — гироскопический пульт;
- метод — порт/тракт на корпусе;
- атрибут — ячейка/слот;
- абстрактный класс — витрина с разомкнутым контуром;
- интерфейс — шестиугольный порт;
- наследование — луч материализации;
- NPC — куратор/оператор/курьер.

Сильные стороны: M показывает форму будущего R, поэтому класс и объект различаются силуэтом, а не подписью; переход «отвердевает» ту же форму.
Слабые: витрина всё ещё может читаться как место; масштабирование до 1000 объектов требует агрегации.

### Заменённый incumbent

**Цех / завод** (`workshop`, 81/100 в первом ревью) — историческая метафора. Причина замены: в ревью 2026-11-13 она провалила главный тест «класс vs объект» — класс читался как место, а не как тип. Решение: [`docs/decisions/0004-visual-metaphor.md`](../../decisions/0004-visual-metaphor.md).

## Как предложить мод

1. Скопируй [`mods/0000-template.md`](mods/0000-template.md).
2. Заполни отображение для всех понятий.
3. Заполни [`scorecard.md`](scorecard.md).
4. Приведи минимум 3 сцены, где мод лучше incumbent.
5. Опиши миграцию: что меняется в `layout.json`, примерах, курсе, NPC.
6. Открой issue с меткой `metaphor` и запусти панель (все 8 ролей).

## Правило замены

Incumbent заменяется, если challenger:

- имеет **семантическую точность ≥ incumbent**;
- имеет **различимость состояний ≥ incumbent**;
- выигрывает минимум по **4 критериям**;
- имеет реальный план миграции;
- проходит self-check на 5 пользователях.

Если challenger лучше только «на вид» — это P3, не замена.

## Допустимые гибриды

Мод может не заменять текущую метафору, а дополнять её:

- **3D-печать** — метафора материализации M → R (кристаллизация уже близка).
- **Театр** — метафора ролей и сценариев для sequence-viewpoint.
- **Город** — метафора масштабирования и районов для L0–L1.
- **Лаборатория** — метафора runtime и экспериментов.

Гибрид допустим, если у него есть явная граница: «витрина — структура, театр — последовательность».

## Кандидаты

| Мод | Статус | Сильная сторона | Риск |
|---|---|---|---|
| `blueprint` | incumbent (provisional) | класс и объект различаются силуэтом; форма сохраняется при переходе | витрина может читаться как место; ждёт user test |
| `workshop` | superseded | методы, runtime, NPC | класс как место |
| `3d-printing` | candidate | класс = модель, объект = печать | слабая runtime-история |
| `city` | candidate | масштаб, районы, LOD | тип vs здание |
| `theater` | candidate | роли, sequence | слабая структура |
| `recipe` | candidate | универсальность | почти нет 3D |
| `laboratory` | candidate | runtime, эксперимент | слабая иерархия |

## Запрещено

- Менять метафору в PR без scorecard.
- Вводить два значения одного визуального признака.
- Называть мод «лучше», не показав 3 сцены.
- Требовать миграцию всех примеров до review.
