# Art Direction & Visual Grammar: Industrial Pipeline (Satisfactory Paradigm)

**Status:** Active Specification (v0.2)  
**Default Theme ID:** `industrial-v1`  
**Architecture:** Modular Core + Pluggable Domain Profiles  
**Audience:** Human Designers, 3D Artists, AI Coding Agents  

---

## 1. Философия и ключевая метафора

UMLG отказывается от плоских абстрактных коробок в пользу **индустриальной производственной метафоры** (референс: *Satisfactory*, *Factorio*). Любая программная система рассматривается как завод по обработке, хранению и маршрутизации данных.

### Архитектурный принцип: Core vs Profiles
В соответствии с Принципом №8 (*«Маленькое ядро, профили для доменов»*), визуальная система строго разделена на два уровня:
1. **Core UMLG:** Минимальный, универсальный набор архитектурных сущностей (`Class`, `Interface`, `Struct`, `Process`, `Store`, `Channel` и др.), не привязанный ни к какому языку, движку или API.
2. **Domain Profiles (Подключаемые расширения):** Опциональные плагины визуализации для конкретных предметных областей (например, `graphics-gpu` для OpenGL/Vulkan, `web-backend`, `robotics`). Профили можно включать и отключать независимо друг от друга. Если профиль отключен, сущности с его префиксом безопасно отображаются через базовые примитивы Core UMLG.

## 2. Контраст миров (M vs R)

Одна и та же 3D-геометрия (процедурная или `.glb` ассет) обязана поддерживать два состояния рендера в зависимости от активного мира наблюдателя:

### M-мир (Мир замысла — Режим проектирования / Голограмма)
* **Визуальный образ:** Архитектурная голограмма перед постройкой (режим Build Gun в *Satisfactory*).
* **Материалы:** Полупрозрачный акрил/стекло (`opacity: 0.25–0.4`), светящиеся силовые ребра (`EdgesGeometry`), холодная сине-голубая палитра (`#00E5FF`, `#0288D1`).
* **Освещение и эффекты:** Мягкий `Bloom` на ребрах, отсутствие жестких теней, координатная сетка (Blueprint Grid) на плоскости основания.
* **Динамика:** Статичная или медленно левитирующая форма без «производственного шума».

### R-мир (Мир воплощения — Работающий завод / Рантайм)
* **Визуальный образ:** Тактильное промышленное оборудование из металла, карбона и керамики с живыми индикаторами нагрузки и потоками ресурсов.
* **Материалы:** Физически корректный PBR (`MeshStandardMaterial`) — матовый окрашенный металл (`roughness: 0.45`, `metalness: 0.75`), темный композит, промышленные оранжевые и изумрудные акценты (`#FF6D00`, `#00E676`).
* **Освещение и эффекты:** Направленный свет с мягкими тенями (`PCFSoftShadowMap`), контактные тени, локальный `Bloom` только для активных индикаторов и потоков данных.
* **Динамика:** Вращение роторов/турбин у активных процессов, бегущие импульсы по трубопроводам и заполнение ячеек хранилищ.

## 3. Словарь сущностей Core UMLG (Ядро)

Базовые сущности без префикса домена. Обязательны для реализации в каждой теме.

| Сущность (`CoreEntityKind`) | Индустриальная метафора | Геометрический силуэт (Процедурный фолбэк) | Поведение в R-мире |
| :--- | :--- | :--- | :--- |
| **`Class`** | **Производственный модуль / Станок** | Цельный монолитный корпус со скошенной верхней частью и сервисным маячком. | Горит индикатор состояния; легкая вибрация при активности. |
| **`AbstractClass`** | **Незавершенная станина / Каркас** | Открытая силовая рама по ребрам с парящим ядром-заглушкой внутри. | Мигающий янтарный маячок «требует воплощения», вращение ядра. |
| **`Interface`** | **Стыковочный фланец / Порт** | Кольцевой промышленный разъем с внутренним контуром стыковки. | Подсвечивается при подключении совместимых связей. |
| **`Struct`** | **Грузовой контейнер / Кассета** | Сегментированный блок с ребрами жесткости и прозрачными слотами данных. | Отображает упакованную структуру полей без активного ротора. |
| **`Enum`** | **Револьверный селектор / Барабан** | Цилиндрический диск с секторами и указателем активного состояния. | Поворачивается на сектор выбранного значения. |
| **`Process`** | **Турбина / Узел трансформации** | Цилиндрический агрегат с открытым внутренним ротором (вход → выход). | Активное вращение ротора; цвет отражает нагрузку. |
| **`Store`** | **Стойка-накопитель / Силос** | Вертикальная промышленная стойка с ярусами светодиодных шкал. | Пошаговое заполнение ярусов данными. |
| **`Channel`** | **Шина / Распределительный коллектор** | Горизонтальная магистраль с капсулами-сообщениями. | Показывает буферизацию и очередность передачи сигналов. |

### Связи ядра (`CoreLinkKind`)
* **`Inheritance`:** Жесткая металлическая ферма/опора снизу вверх (без движения частиц).
* **`Composition`:** Жесткая стяжка / крепежная балка между модулями.
* **`DataFlow`:** Световодный трубопровод (`TubeGeometry`) с бегущими импульсами данных в R-мире.
* **`ControlFlow`:** Тонкая сигнальная магистраль управляющих вызовов.
* **`Dependency`:** Пунктирный или тонкий вспомогательный кабель.

## 4. Подключаемые доменные профили (Domain Profiles)

Расширения используют префикс пространства имён (`namespace:EntityKind`) в `model.json` и подключаются через `ThemeManager.registerPlugin()`.

### Профиль `graphics-gpu` (OpenGL / Vulkan Extension)
Предназначен для изучения и проектирования графических конвейеров. Может быть полностью отключен в проектах, не связанных с компьютерной графикой.

| Сущность профиля | Индустриальная метафора | Визуальный силуэт | Назначение при обучении |
| :--- | :--- | :--- | :--- |
| **`gpu:Buffer`** | **Сырьевой бункер (VBO / EBO / UBO)** | Промышленный контейнер с прозрачным окном и сегментами вершин/индексов. | Показывает хранение сырых массивов в памяти GPU. |
| **`gpu:VertexLayout`** | **Распределительный щит (VAO / InputState)** | Плоская коммутационная панель с гнездами атрибутов (`location = 0, 1...`). | Объясняет маппинг буферов на входы вершинного шейдера. |
| **`gpu:ShaderStage`** | **Оптическая призма (Vertex / Fragment / Compute)** | Шестигранный кожух с вращающимся кристаллом внутри (цвет зависит от стадии). | Разделяет геометрическую трансформацию (VS) и окраску пикселей (FS). |
| **`gpu:Pipeline`** | **Главный сборочный туннель (ShaderProgram / VkPipeline)** | Промышленная галерея с силовыми арками, объединяющая стадии конвейера. | Демонстрирует полный путь от вершин до пикселей. |
| **`gpu:Texture`** | **Резервуар пигмента и линза (Texture / Sampler)** | Цилиндрическая цистерна с оптической линзой фильтрации. | Показывает выборку текселей и фильтрацию во фрагментном шейдере. |
| **`gpu:Descriptor`** | **Шина регуляторов (Uniform / DescriptorSet)** | Управляющая рейка с индикаторами параметров (MVP-матрицы, свет). | Отделяет динамические параметры кадра от геометрии. |
| **`gpu:Framebuffer`** | **Финальный терминал вывода (FBO / Swapchain)** | Мониторный модуль с экраном результата и слотами Color/Depth/Stencil. | Отображает итог рендера (например, `Hello Triangle`). |
| **`gpu:CommandQueue`** | **Лента команд (CommandBuffer / VkQueue)** | Конвейерная дорожка с капсулами вызовов отрисовки (`DrawCall`). | Показывает порядок отправки команд с CPU на GPU. |

## 5. Файловая структура и версионирование тем

Вся визуальная логика изолирована в `viewer/src/themes/` и не затрагивает `schema/` или `tools/validate.py`:

```text
viewer/src/themes/
  ├── types.ts                        # Контракты CoreEntityKind, ThemeDefinition, VisualProfilePlugin
  ├── registry.ts                     # ThemeManager (переключение тем и включение/отключение профилей)
  ├── minimal-v0.ts                   # Legacy / Debug: базовые геометрические примитивы
  └── industrial-v1/
        ├── index.ts                  # Сборка темы industrial-v1
        ├── materials.ts              # PBR-материалы R-мира, голограммы M-мира и настройки Bloom
        ├── core-primitives.ts        # Реализация 8 базовых сущностей Core UMLG
        └── profiles/
              └── graphics-gpu.ts     # Опциональный плагин для OpenGL / Vulkan
```

### Реестр версий
* **`minimal-v0`:** Базовые кубы и линии для отладки и слабых устройств.
* **`industrial-v1` (Активная цель):** Процедурные промышленные силуэты в стиле *Satisfactory* + `UnrealBloomPass` + поддержка плагинов.
* **`industrial-v2` (Planned):** Загрузка детализированных `.glb` моделей (созданных в Blender) с автоматическим откатом на процедурные силуэты `industrial-v1`.
* **`blueprint-cad-v1` (Planned):** Высококонтрастный ортографический режим для документации и доступности.

## 6. Итерационный протокол для ИИ-агентов

1. **Неприкосновенность ядра:** Запрещено добавлять доменные сущности (вроде `Shader` или `Database`) в `CoreEntityKind`. Новые домены оформляются только как `VisualProfilePlugin` со своим префиксом.
2. **Безопасный фолбэк:** Если в `model.json` встречается сущность из отключенного профиля, `ThemeManager` обязан отрендерить её через базовый примитив ядра (`Process` или `Store`), не вызывая ошибок.
3. **Сначала силуэт, потом детали:** При создании нового примитива сначала добивайтесь узнаваемости силуэта в M- и R-мирах, затем добавляйте анимацию и пост-эффекты.
4. **Журнал изменений:** Любые предложения по новым метафорам или корректировке палитры фиксируются в секции 7 этого файла.
