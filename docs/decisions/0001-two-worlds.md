# 0001 — Два мира как онтологии

- Статус: accepted
- Дата: 2026-11-12
- Контекст: v0.1

## Решение

UMLG использует минимум два мира:

- **M — Замысел**: типы, контракты, инварианты, абстракции.
- **R — Воплощение**: объекты, ресурсы, процессы, runtime-факты.

Мир — не слой и не тема оформления. Это набор правил о том, что может существовать.

## Причины

1. UML смешивает проектирование и runtime, из-за чего абстрактный класс и объект визуально неразличимы.
2. Призрак получает точный смысл: существует в M, не материализуется в R.
3. Появляется трассируемость «класс ↔ объект».
4. Становится возможным явный drift.

## Следствия

- Присутствие ровно одно; второй мир не рендерится.
- `abstractClass` не может быть источником `materializes`.
- У каждого R-объекта ровно один материализующий класс.
- S-мир (код) зарезервирован, но не реализован в v0.1.

## Альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Один мир + слои | слои не дают онтологических правил, призрак снова размывается |
| UML + runtime-оверлей | runtime остаётся вторичным, drift не виден |
| Три мира сразу (M/S/R) | удваивает сложность v0.1 |
