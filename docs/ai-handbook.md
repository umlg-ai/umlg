# AI Handbook

Практическое руководство для ИИ-агентов, которые правят UMLG.
Дополняет [`AGENTS.md`](../AGENTS.md), не заменяет его.

## 1. Одностраничная модель

```
                    M — Замысел
        типы, контракты, абстракции, инварианты
                        │
          materializes  │  (только от конкретных классов)
                        ▼
                    R — Воплощение
        объекты, ресурсы, процессы, runtime-факты
```

Правила, которые нельзя нарушать:

- присутствие ровно одно;
- второй мир не рендерится;
- абстрактный класс не материализуется;
- модель и layout разделены;
- переход — фазовый сдвиг, не портал.

## 2. Онтология в таблицах

### 2.1 Элементы

| `kind` | Мир | Что это | Аналог |
|---|---|---|---|
| `class` | M | конкретный тип | типовой проект цеха |
| `abstractClass` | M | тип без прямой материализации | призрак цеха |
| `interface` | M | контракт | стыковочный узел |
| `component` | M | модуль/подсистема | район |
| `concept` | M | понятие, решение, паттерн | плакат/регламент |
| `object` | R | экземпляр | работающий цех |
| `resource` | R | буфер, текстура, framebuffer | склад/резервуар |
| `process` | R | поток/процесс | бригада |
| `stage` | R | стадия конвейера | участок линии |
| `command` | R | вызов/команда | наряд |
| `actor` | R | CPU/GPU/сервис | оператор |

### 2.3 Межмировые ссылки

| `kind` | Из | В | Проверка |
|---|---|---|---|
| `materializes` | M-класс | R-сущность | источник не `abstractClass` |
| `implements` | M-интерфейс | M-класс | обе стороны в M |
| `deploys` | M-компонент | R-процесс | M → R |
| `observes` | R-факт | M-элемент | R → M |
| `drift` | M-элемент | R-элемент | M → R, диагностика |

## 5. Правила расширения схемы

Порядок обязателен:

1. **Спецификация.** Опиши поле в `spec/05-serialization.md`: зачем, тип, ограничения, пример.
2. **Схема.** Добавь поле в `schema/*.json`. Новое поле — опциональное, если нет веской причины.
3. **Пример.** Обнови `examples/hello-triangle/` или добавь новый.
4. **Валидатор.** Если поле имеет семантику — добавь проверку в `tools/validate.py`.
5. **CHANGELOG.** Опиши изменение.
6. **Версия.** Новое необязательное поле — minor. Несовместимое — major.
7. **`make validate`.**

Запрещено:

- добавлять поле только в схему, без спецификации;
- добавлять enum-значение, которое не описано в спеке;
- менять смысл существующего поля без major и миграции.

## 6. Типовые ошибки ИИ-агентов

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Добавить координаты в `model.json` | смешение семантики и презентации | `layout.json` |
| Сделать `abstractClass` источником `materializes` | ломает онтологию призрака | выбрать подкласс |
| Показать второй мир полупрозрачным | нарушает правило присутствия | только метаданные двойника |
| Сделать NPC источником типов/кратностей | модель станет непроверяемой | инспектор + модель |
| Добавить новую сущность «для красоты» | раздувание ядра | 3–5 тем, потом RFC |
| Скопировать текст/картинку LearnOpenGL | юридический риск | ссылка + своя схема |
| Сделать `flow` внутри M-мира | нарушение world ↔ kind | `dependency`/`association` |
| Сделать `inheritance` в R-мире | нарушение world ↔ kind | `materializes` + M-связь |
| Оставить `id` с пробелами | ломает layout/ссылки | `m.class.circle` |
| Молча поменять семантику | ломает доверие и модели | issue/RFC/CHANGELOG |

## 7. Призрак: чек-лист

Абстрактный класс:

- `kind: abstractClass`, тег `ghost`;
- та же геометрия и позиция, что у обычного класса;
- холодный полупрозрачный материал, нет тени;
- имя курсивом + бейдж `{abstract}`;
- вход заблокирован;
- нет `materializes`;
- при попытке материализации — выбор подкласса.

Не путать с:

- `deprecated` — ржавчина и лента;
- `unused` — приглушённый, но solid;
- `deleted` — руины;
- `mock` — яркий манекен;
- `proxy` — зеркало/док;
- `sealed` — запертые ворота.

## 8. Переход: чек-лист

- удержание 200 мс (VR 250 мс), кулдаун 500 мс;
- 0.15 с intent → 0.55 с phase → 0.30 с arrival;
- M → R: кристаллизация; R → M: сублимация;
- камера не двигается (кроме FOV 1–2%);
- второй мир не рендерится;
- фокус сохраняется;
- без фокуса — те же координаты;
- абстрактный класс — выбор подкласса;
- `reduced motion` — мгновенно;
- направление дублируется текстом и звуком/haptic.

## 9. Тестирование

### 9.1 Self-check

Каждая тема обязана иметь 5–7 вопросов с эталонными ответами.
Критерий: новый пользователь отвечает без подсказок.

### 9.2 Usability-тест

5–8 участников, think-aloud, задачи:

- найди метод;
- объясни связь;
- предскажи результат вызова;
- отличи класс от объекта;
- объясни, почему у призрака нет экземпляров.

Метрики: время, ошибки, уверенность, SUS/NASA-TLX.
Повтор через неделю — проверка удержания.

### 9.3 Видео-демо

Видео — это **тест объяснимости** и инструмент привлечения, а не замена usability-тесту.
Если сцену нельзя связно объяснить за 90 секунд, модель слишком сложна или грамматика врёт.

Сценарий и раскадровка: [`docs/video/hello-triangle-demo.md`](video/hello-triangle-demo.md).

## 10. Глоссарий

| Термин | Значение |
|---|---|
| M-мир | онтология замысла: типы, контракты, инварианты |
| R-мир | онтология воплощения: объекты, ресурсы, runtime |
| Призрак | абстрактный класс: существует в M, не материализуется |
| Двойник | соответствующая сущность в другом мире |
| Материализация | создание R-сущности по M-типу |
| Drift | обнаруженное расхождение модели и реальности |
| Viewpoint | контракт: вопрос, что видно, что скрыто |
| Фазовый переход | смена законов мира вокруг наблюдателя |
| Кристаллизация | эффект M → R |
| Сублимация | эффект R → M |
| NPC | семантический агент, генерируемый из модели |
| LOD | уровень детализации |
