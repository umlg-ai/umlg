# Contributing

## Главное правило

Не добавляй новую сущность в ядро UMLG, пока она не доказала необходимость на **3–5 темах курса**. Сначала — пример, потом — язык.

## Что можно предложить

- новый viewpoint;
- новую визуальную переменную;
- улучшение перехода M ↔ R;
- тему курса по шаблону Topic Card;
- исправление схемы или примера;
- тест понятности.

## Процесс

1. Открой issue с описанием задачи и критерием успеха.
2. Для изменений ядра — RFC в `docs/rfcs/` (шаблон: [`docs/rfcs/0000-template.md`](docs/rfcs/0000-template.md)).
3. Один PR — одно смысловое изменение.
4. `make validate` должен проходить.
5. Текст и изображения — только оригинальные или с совместимой лицензией.

## ИИ-агенты

Если правку вносит ИИ:

1. Прочитай [`AGENTS.md`](AGENTS.md) целиком.
2. Не меняй семантику молча: сомнение → issue или RFC.
3. Не добавляй поля в JSON без обновления `spec/05-serialization.md`.
4. Не копируй чужие текст/код/изображения.
5. Прогони `make validate` и приложи результат в PR.

## Валидация

```bash
make validate
```

Отдельно:

```bash
make json        # синтаксис JSON
make schema      # JSON Schema 2020-12 через ajv
make semantics   # ID, ссылки, миры, materializes
make links       # относительные ссылки в Markdown
```

## Стиль

- Ключи JSON — `camelCase`, значения `enum` — `kebab-case`.
- ID стабильные, человекочитаемые: `m.app`, `r.vao`, `m.rel.app.window`.
- В документации — русский язык; идентификаторы — английские.
- Не смешивай семантику и презентацию: координаты, цвет и размер — только в `layout.json`.

## Контент курса

- Не копируй текст, код и изображения LearnOpenGL без разрешения.
- Ссылайся на источник и делай собственные схемы.
- Каждая тема оформляется по Topic Card: цель, M-модель, R-модель, ошибки, упражнения, self-check.
