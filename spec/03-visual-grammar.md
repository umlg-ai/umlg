# 03 — Визуальная грамматика

## 1. Базовая метафора: цех

Архитектура читается как промышленный комплекс:

```
комплекс → район → цех → станок → операция
```

| Уровень UMLG | Аналог | Что означает |
|---|---|---|
| система | комплекс | вся модель |
| модуль/пакет | район | группа связанных типов |
| класс | типовой проект цеха | тип, контракт, возможность |
| объект | работающий цех | экземпляр, факт, runtime |
| метод | станок | операция над состоянием |
| атрибут | склад/резервуар | состояние |
| связь | дорога/труба/луч | отношение |

Метафора нужна не для украшения, а чтобы пользователь мог **угадывать семантику до чтения подписей**. Если метафора врёт, она удаляется.

## 2. Класс: типовой проект

Класс — это **не** работающий цех. Это проект, по которому можно построить цех.

Визуальные признаки:

- голограмма/чертёж, полупрозрачные стены;
- контур чёткий, материал нематериальный;
- внутри видны макеты станков и складов, но они не работают;
- вывеска с именем типа;
- NPC-инструктор, а не оператор.

Почему не solid: solid означает «существует и работает». Если класс выглядит как работающий цех, пользователь перестаёт различать тип и экземпляр — это главная ошибка, которую UMLG должен предотвращать.

## 3. Объект: работающий цех

Объект:

- solid-геометрия, материал, вес;
- работающие станки;
- NPC-операторы, очереди, датчики;
- следы времени: износ, температура, ошибки;
- имя вида `Circle#2`.

Один класс может дать много объектов. Они не обязаны стоять рядом, но layout по умолчанию старается держать их в зоне видимости класса — для пространственной памяти.

## 4. Абстрактный класс: призрак

### 4.1 Определение

> Абстрактный класс — сущность M-мира, которая не может быть материализована напрямую и не имеет runtime-прошлого.

Это точнее, чем «мёртвый» или «нереализованный».

### 4.2 Визуал

- та же геометрия и то же место, что у обычного класса;
- холодный полупрозрачный материал;
- отсутствие тени, но чёткий контур;
- имя курсивом + бейдж `{abstract}` + иконка призрака;
- вход заблокирован: «прямое создание невозможно»;
- NPC — голографический бригадир, объясняющий контракт.

### 4.3 Чего призрак **не** означает

| Не означает | Как отличить |
|---|---|
| `deprecated` | ржавчина, оградительная лента, бейдж `deprecated` |
| `unused` | приглушённый, но solid; бейдж `unused` |
| `deleted` | руины/пепел, нет контура |
| `mock/stub` | яркий голограммный манекен, бейдж `mock` |
| `remote/proxy` | зеркало/док, бейдж `proxy` |
| `sealed/final` | запертые ворота, бейдж `sealed` |

Один и тот же полупрозрачный вид не может означать пять разных вещей. Это правило важнее красоты.

### 4.4 Призрачность члена ≠ призрачность класса

| Что | Визуал | Смысл |
|---|---|---|
| абстрактный класс | призрачная оболочка | нельзя создать напрямую |
| абстрактный метод | пустой пунктирный слот станка | реализации нет |
| конкретный метод в абстрактном классе | призрачный, но работающий станок | реализация есть, наследуется |
| атрибут абстрактного класса | призрачный склад с меткой `inherited` | состояние живёт в подклассах |
| конструктор | призрачная пусконаладка | вызывается только через подкласс |
| статический член | solid общий склад вне цеха | реален и общий |

Правило: **абстрактный класс — призрачный, но не обязательно пустой.**

### 4.5 Материализация призрака

Попытка создать экземпляр абстрактного класса:

1. открывает «ворота материализации»;
2. показывает список конкретных подклассов;
3. объясняет, какой контракт каждый выполняет;
4. после выбора создаёт объект подкласса;
5. подсвечивает линию наследования как «луч материализации».

Это не ошибка, а обучающий момент.

## 5. Интерфейс: контрактный узел

Интерфейс — не цех. Это:

- парящий стыковочный порт;
- сертификат/разъём;
- набор обязательств без тела и состояния.

Визуал:

- нет стен и складов;
- есть только порты/разъёмы с сигнатурами;
- соединяется с классами линией реализации (пунктир + треугольник);
- бейдж `{interface}`.

Почему не призрак: призрак — это «цех, который нельзя построить». Интерфейс — это «стандарт, которому можно соответствовать». Разные онтологии, разный визуал.

## 6. Члены класса

### 6.1 Атрибут

- склад/резервуар/пульт;
- имя и тип на табличке;
- видимость: замок (private), ключ-карта (protected), открытые ворота (public);
- `static` — общий склад вне цеха;
- `const`/`readonly` — опечатанный контейнер;
- `optional` — пустая ячейка с пунктиром.

### 6.2 Метод

- станок/линия;
- табличка с именем и сигнатурой;
- параметры — входной конвейер с ящиками;
- возврат — выходной конвейер;
- `abstract` — пустой пунктирный слот;
- `static` — передвижной инструмент;
- `async` — линия с буфером ожидания.

### 6.3 Свойство (getter/setter)

- клапан/датчик;
- показывает значение;
- `readonly` — только датчик, без клапана.

### 6.4 Событие/сигнал

- сирена/лампа;
- мигает при срабатывании (не чаще 3 Гц);
- не является методом: у него нет входа-конвейера.

### 6.5 Исключение

- аварийный выход;
- красная сигнализация;
- путь эвакуации к обработчику.

### 6.6 Инвариант

- плакат правил безопасности на стене;
- при нарушении краснеет и вызывает инспектора;
- не является исполняемым элементом.

## 7. Связи

| UML | Визуал | Направление | Подпись |
|---|---|---|---|
| наследование | луч материализации снизу вверх | подкласс → суперкласс | `extends` |
| реализация | пунктир к контрактному узлу | класс → интерфейс | `implements` |
| композиция | станки внутри цеха, жёсткая связь | целое → часть | ромб + кратность |
| агрегация | общий инструмент, съёмная связь | целое → часть | пустой ромб |
| ассоциация | дорога/труба | любой | роль + кратность |
| зависимость | временная поставка, пунктир | зависимый → зависимость | `uses` |
| поток | полоса движения | источник → сток | объём/частота |
| вызов | курьер/сигнал | вызывающий → вызываемый | сигнатура |
| сигнал | сирена | источник → слушатели | имя события |
| привязка | кабель/док | потребитель → ресурс | слот/индекс |

Правила:

1. **Положение не создаёт связь.** Линия обязательна.
2. **Кратность — текст, не толщина.** Толщина может кодировать поток, но не `1..*`.
3. **Роль — текст у конца линии.**
4. **Цвет линии — только состояние** (`drift`, `deprecated`, `active`).
5. **Пересечения минимизируются**, но не любой ценой: лучше честная линия, чем ложная группировка.

## 8. NPC

NPC — семантические агенты. Их поведение генерируется из модели, а не рисуется вручную.

| NPC | Отвечает за | Пример действия |
|---|---|---|
| Бригадир | класс | объясняет назначение, инварианты, жизненный цикл |
| Оператор | метод | берёт параметры, запускает станок, выдаёт результат |
| Курьер | связь/вызов | движется между цехами; частота = частота вызовов |
| Инспектор | формальные данные | по запросу показывает сигнатуру, тип, кратность |
| Охранник | видимость/доступ | блокирует приватное |
| Диспетчер | полиморфизм | выбирает реализацию |
| Техник по безопасности | исключения/инварианты | реагирует на нарушения |

Жёсткие правила:

1. **NPC не заменяют формальные данные.** Точная сигнатура всегда доступна в инспекторском киоске.
2. **NPC не кодируют тип, кратность и видимость.** Это делают геометрия и текст.
3. **Поведение NPC выводится из модели.** Если для каждого метода нужен свой аниматор, проект не масштабируется.
4. **NPC можно отключить.** Architecture mode работает без них.

## 9. Режимы чтения

| Режим | NPC | Подписи | Анимация | Для кого |
|---|---|---|---|---|
| `story` | включены | минимальные | есть | новички, обучение |
| `architecture` | приглушены/выключены | полные | минимум | ревью, проектирование |
| `debug` | агенты runtime | метрики | живая | отладка |
| `presentation` | по сценарию | крупные | кинематографичная | демонстрация |

Плотность семантики — ползунок от «только имена» до «полная карточка». Это ответ на «понятно всем»: новичок начинает со `story`, архитектор сразу включает `architecture`.

## 10. Визуальные переменные

Разрешённые каналы и их значения:

| Канал | Допустимые значения | Запрещено |
|---|---|---|
| материал | ghost / hologram / solid / rust / glass | произвольные текстуры без смысла |
| прозрачность | уровень существования (0.2–0.6 ghost) | декор |
| цвет | состояние (normal/deprecated/drift/error) | кодирование типа |
| контур | чёткий / пунктир / отсутствует | случайный |
| движение | поток, вызов, сигнал | декоративная анимация |
| звук | мир, переход, авария | фоновая музыка как семантика |
| размер | фиксирован по уровню | «важность» |
| положение | группировка/вложенность | «важность» |

Правило: **если канал не описан в этой таблице, он не кодирует семантику.**

## 11. LOD (уровни детализации)

| Уровень | Что видно | Когда |
|---|---|---|
| L0 | район/комплекс, только имена | обзор |
| L1 | цеха, ключевые связи | навигация |
| L2 | члены класса, подписи | работа |
| L3 | сигнатуры, типы, кратности, инварианты | ревью |
| L4 | история, метрики, провенанс | отладка |

Правила:

- переход между LOD плавный и обратимо;
- LOD не меняет семантику, только детализацию;
- на L0 связи не исчезают бесследно: остаются агрегированные пучки;
- LOD по умолчанию зависит от расстояния и режима чтения.

## 12. Масштабирование

| Количество | Представление |
|---|---|
| 1 объект | отдельный цех |
| 2–20 | отдельные цеха |
| 20–1000 | кварталы/ряды, агрегированные |
| > 1000 | облако/толпа, статистика |

Один объект = один экземпляр. Тысяча = облако, а не тысяча NPC.

## 13. Где метафора ломается

Эти случаи должны быть спроектированы явно:

| Случай | Решение |
|---|---|
| Generic-класс | цех-конструктор с контейнерами `T` |
| Вложенный класс | цех внутри цеха, отдельный вход |
| Singleton | единственный цех с одним ключом |
| Enum | набор маркированных ящиков |
| Лямбда | переносной инструмент |
| Record/struct | небольшой поддон, не цех |
| Модуль/пакет | район |
| Функция без класса | отдельный станок на площади |
| Макрос/декоратор | наклейка/модификатор на станке |
| Множественное наследование | несколько лучей материализации, конфликт подсвечивается |

Если случай не покрыт, он не «выкручивается» визуально на месте, а добавляется в спецификацию.

## 14. Проверка грамматики

Минимальный тест:

1. Пользователь находит метод за 10 секунд.
2. Пользователь отличает класс от объекта без подсказки.
3. Пользователь объясняет, почему у призрака нет экземпляров.
4. Пользователь различает `abstract` и `deprecated`.
5. Пользователь читает кратность связи.

Если хотя бы один пункт провален — правится грамматика, а не пользователь.
