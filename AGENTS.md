# AGENTS.md

Инструкции для ИИ-агентов и людей, которые вносят правки в UMLG.
Читай этот файл целиком перед изменением репозитория.

## 1. Что это

UMLG — визуальный язык архитектуры с двумя онтологиями:

- **M — Замысел**: типы, контракты, инварианты, призраки.
- **R — Воплощение**: объекты, ресурсы, процессы, runtime-факты.

Переход между мирами — фазовый сдвиг вокруг наблюдателя, а не портал.
3D — основная среда, но семантика не зависит от рендерера.

Статус: **v0.1 draft**. Один вертикальный срез — `Hello Triangle`.

## 2. Обязательное чтение

Перед любой содержательной правкой прочитай:

1. [`spec/00-manifest.md`](spec/00-manifest.md) — цели, non-goals, принципы.
2. [`spec/01-worlds.md`](spec/01-worlds.md) — онтология M/R и инварианты.
3. [`spec/05-serialization.md`](spec/05-serialization.md) — модель, layout, ID.
4. [`docs/ai-handbook.md`](docs/ai-handbook.md) — карта репозитория и типовые ошибки.

Если правка касается визуала — [`spec/03-visual-grammar.md`](spec/03-visual-grammar.md).
Если переходов — [`spec/04-transitions.md`](spec/04-transitions.md).
Если темы курса — [`course/README.md`](course/README.md).

## 3. Жёсткие инварианты

Нарушение любого пункта — блокирующая ошибка.

1. **Одно присутствие.** Пользователь не может действовать в двух мирах одновременно.
2. **Другой мир не рендерится.** Ни сквозь прозрачность, ни crossfade, ни превью.
3. **Семантика ≠ презентация.** Координаты, цвет, материал, камера — только в `layout.json`.
4. **Абстрактный класс не материализуется напрямую.** Валидатор это проверяет.
5. **У каждого R-объекта ровно один `materializes`.** Иначе — `drift` или ошибка.
6. **ID стабильны.** Переименование `name` не меняет `id`.
7. **Нет совместимости с UML/XMI в v0.1.** Не добавляй импорт/экспорт «на всякий случай».
8. **Новая сущность ядра — только после 3–5 тем курса.** Сначала пример, потом язык.
9. **Никакого копирования LearnOpenGL.** Только ссылки, атрибуция и собственные схемы.
10. **Валидация обязательна.** Без `make validate` правка не готова.

## 5. Команды

```bash
make validate   # JSON + schema + семантика + ссылки
make links      # только ссылки
make fmt        # форматирование JSON (если настроено)
```

Вручную:

```bash
python3 tools/validate.py examples/hello-triangle/model.json examples/hello-triangle/layout.json
npx --yes ajv-cli@5 validate --spec=draft2020 -s schema/umlg.schema.json -d "examples/**/model.json"
npx --yes ajv-cli@5 validate --spec=draft2020 -s schema/layout.schema.json -d "examples/**/layout.json"
python3 tools/check_links.py
```

## 6. Как вносить изменения

### 6.1 Новая тема курса

1. Скопируй структуру [`course/hello-triangle.md`](course/hello-triangle.md).
2. Заполни все 10 разделов, включая ошибки, упражнения и self-check.
3. Добавь M- и R-модель в `examples/<topic>/`.
4. Добавь строку в матрицу [`course/README.md`](course/README.md).
5. Проверь, что не появилось новых сущностей ядра. Если появились — сначала RFC в `docs/rfcs/`.
6. `make validate`.

### 6.2 Новый viewpoint

1. Сформулируй вопрос одной фразой.
2. Докажи, что его нельзя выразить композицией существующих.
3. Проверь на 3 темах.
4. Обнови `spec/02-viewpoints.md` и enum в схеме, если нужно.
5. Добавь self-check вопрос.
6. `make validate`.

### 6.3 Новый вид элемента или связи

Это изменение ядра. Требуется:

1. RFC в `docs/rfcs/NNNN-<slug>.md` (шаблон: [`docs/rfcs/0000-template.md`](docs/rfcs/0000-template.md)).
2. Минимум 3 примера, где без этого нельзя.
3. Обновление `spec/01-worlds.md`, `spec/05-serialization.md`, схемы.
4. Обновление валидатора и тестов.
5. Повышение minor-версии.

Без RFC — не merge.

### 6.4 Правка схемы

Порядок:

1. `spec/05-serialization.md` — сначала описание.
2. `schema/*.json` — потом схема.
3. `examples/*` — рабочий пример.
4. `tools/validate.py` — семантические проверки.
5. `CHANGELOG.md`.
6. `make validate`.

Не добавляй поле, которое не описано в спецификации.

## 7. Стиль

- Документация — русский язык.
- Идентификаторы, ключи JSON, enum — английский.
- JSON-ключи — `camelCase`.
- Значения enum — `kebab-case` (кроме `kind`, где исторически `camelCase`: `abstractClass`).
- ID: `<world>.<kind-short>.<local-id>`, например `m.class.circle`, `r.obj.circle-1`.
- Связи имеют собственные ID: `m.rel.circle.extends.shape`.
- Один PR — одно смысловое изменение.

## 8. Чего не делать

- Не добавлять «умные» поля в `layout.json` (тип, кратность, abstract).
- Не кодировать тип цветом, если это не описано в визуальной грамматике.
- Не делать NPC источником истины: точные данные — в инспекторе.
- Не добавлять красивую анимацию, которая не следует из модели.
- Не писать «UML-совместимо», если это не проверено.
- Не менять семантику молча: если сомневаешься — issue или RFC.
- Не коммитить сгенерированные `node_modules/`, `dist/`, `__pycache__/`.

## 9. Definition of Done

Правка готова, если:

- [ ] `make validate` проходит;
- [ ] обновлены спецификация и схема (если менялся формат);
- [ ] обновлён пример или добавлен новый;
- [ ] обновлён `CHANGELOG.md` при изменении поведения;
- [ ] нет новых сущностей без RFC;
- [ ] ссылки в Markdown не битые;
- [ ] текст и изображения — оригинальные или совместимые по лицензии.

## 10. Текущий фокус

M1 — vertical slice:

1. Web-вьюер: загрузка `model.json` + `layout.json`.
2. M-мир: цеха, призрак `Shader`, связи, инспектор.
3. R-мир: объекты, ресурсы, конвейер, агенты.
4. Фазовый переход M ↔ R.
5. HUD мира и двойника.
6. Видео-демо 90–120 с.

Не начинай `Hello Window`, пока `Hello Triangle` не проходит self-check на людях.
